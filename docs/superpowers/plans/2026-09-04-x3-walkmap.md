# X3 offline walkmap implementation plan

> Execute task-by-task with the executing-plans workflow and bounded DeepSeek delegation. Codex owns format, integration and final acceptance. No commits, deployment or device changes.

**Goal:** Optional SD walking-path context beneath the existing GPX overview.
**Architecture:** Independent indexed map, streamed visible cells, route-only fallback.
**Tech stack:** Python standard library converter; allocation-free C++17 reader; existing native renderer and SdFat.
**Spec:** `docs/superpowers/specs/2026-09-04-x3-walkmap-design.md`

## Constraints

Keep existing route storage, partition layout and dashboard unchanged. One writer per worktree. All large artifacts under `/Volumes/2TB/x3-navigation-next-20260904`. No secrets, production writes, dependency installation, or device access. Software success does not establish hardware performance. This increment intentionally does not deliver live GPS, power policy, names/landscape, or full regional coverage.

## 1. Converter and binary fixture

Files: `tools/walkmap/build_walkmap.py`, `tools/walkmap/test_build_walkmap.py`, `test/fixtures/walkmap-v1.osm`, `test/fixtures/walkmap-v1.bin`.

- [ ] Write tests first for `build(input_path, output_path)` producing the specified X3WM header, directory and cell CRCs from a synthetic crossing-path OSM XML fixture. Assert path classes, restricted flags, exact endpoint retention and rejection of missing nodes/nonfinite coordinates/oversized grid. Run `python3 -m unittest discover -s tools/walkmap -v`; first run must fail on missing implementation.
- [ ] Implement two-pass XML parsing using standard-library sqlite3 for bounded node lookup, with temporary database next to output and explicit cleanup of only its own temporary file. Reject existing output unless CLI has explicit overwrite flag. Write a sibling temporary package and publish only after successful validation. No network. Report retained/skipped way counts.
- [ ] Generate deterministic synthetic binary fixture. Run converter tests and record its SHA-256. The fixture is not geographic coverage evidence.

## 2. Portable cell reader

Files: `src/spikes/navigator/map/WalkMap.h`, `.cpp`, `test/navigator/WalkMapTest.cpp`, `test/navigator/CMakeLists.txt`.

- [ ] Add failing tests consuming the converter fixture and corrupted variants. Interface: `WalkMapByteSource::size/read`; `WalkMap::open(source)`, `WalkMap::visit(source, GeoBounds, callback, context)`; callback receives `WalkMapEdge` with E7 endpoints/class/flags. Status distinguishes invalid data, read failure, budget exceeded and success.
- [ ] Validate immutable metadata/directory before publishing small index; revalidate selected directory entries and cells per draw. Bound every read to 256 bytes; reject read over-reporting. Validate selected cells before invoking their callbacks. Enforce 1024-cell/100000-edge budget and world/cell geometry bounds.
- [ ] Run real NavigatorCoreTest, then sanitizer build with same focused suite. No shim acceptance.

## 3. Screen integration and SD reader

Files: `map/WalkMapSdSource.h/.cpp`, `map/RouteMapRenderer.h/.cpp`, `NavScreenRenderer.h/.cpp`, `NavigatorMain.cpp`, related navigator tests.

- [ ] Write framebuffer/order/fallback tests before implementation. Add optional background input to existing draw path, default absent. Reuse clipping, draw one-pixel map beneath five-pixel overview route, preserve marker-last and disconnected GPX.
- [ ] Implement read-only canonical map adapter, closing each handle. Load after SD mount and reload in existing manual receiver path. Keep at most a small static map descriptor, no full index or second framebuffer.
- [ ] On any map failure clear map region and draw route-only; no plausible partial basemap. Show map status and attribution when applicable. Add a conservative viewport geographic-bound helper if needed, with edge/antimeridian tests.
- [ ] Run navigator tests and a clean `navigator-x3` target build using external build directory. Check binary size and actual object inclusion; no flash.

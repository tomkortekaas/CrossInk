## Baseline evidence

The supplied known-good firmware was identified as SHA-256
`478e83617cfe2467c7b3be919da139390e8ea3d145ab6fdd2ab821504456866a`,
size 6,303,088 bytes, with source commit `e2563607`. A clean local rebuild
of that source in the current toolchain produced 6,323,968 bytes and SHA-256
`6b83a58f8f527a3908166e3ad7fab9369011b8fbcf5f8287d822478497bb2c41`.
The difference is retained as build-environment evidence; the historical
binary was not treated as reproducible without its exact original toolchain.

The baseline host suite exposed eight pre-existing non-English
`HyphenationEval` failures. This fork intentionally compiles only English
hyphenation data to conserve flash. Those eight cases were recorded as
baseline debt and excluded consistently; all other baseline tests passed.

## CrossInk merge and SDK forward-port

CrossInk v1.6.0 was merged as commit
`e35199b05a894e951fd010c35300135f673117a0`. The X3 GPIO13 battery-latch,
timer-wake power behavior, and SD shutdown changes were forward-ported onto
the v1.6.0 SDK base. A follow-up SDK repair consolidated the new SPI/SDMMC
shutdown implementations into one idempotent path.

Target-build failures were repaired in separate commits for SDK-config
inheritance, reduced-language i18n, dashboard font metadata, BLE receiver
navigation linkage, and simulator-only hardware exclusions. The final map
contains `dashboard::runReceiverWindow`, both dashboard V3 render entry
points, `SDCardManager::shutdown()`, and
`freeink::PowerManager::holdPowerRailsForTimerWake()`.

## Required hardware acceptance

1. Connect the known X3 only after separate user authorization.
2. Read chip identity, partition table, OTA data, and a fresh full-flash backup.
3. Verify the backup hash and store it outside the repository.
4. Determine the active app slot and exact safe candidate offset.
5. Flash only the approved slot/offset.
6. Test boot, dashboard, book/manual sleep, BLE-to-reader handoff, one timer
   wake, day/night transitions, then a 20–30 wake soak.
7. Restore the full backup if any power, boot, storage, reader, or BLE
   regression appears.
